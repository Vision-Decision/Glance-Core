# v1.2 退步诊断（供 v1.3 定配比）

v1.2 在四处退步。这里按单条结果配对比较 v1.1 和 v1.2：两者用同一份评测文件，逐行对齐并核对表达式文本；然后按错误类型和简单的文本特征，把退步拆开。

- 脚本：`scripts/v12/regress_diag.py`
- 原始结果：`results/regress_diag.json`
- 文本特征包括：长度、方位词、关系词、数字、是否含类别词
- 下表"净变化"一列 = v1.2 新答对的条数 − 新答错的条数，换算成百分点

| 退步项 | 净变化 | 新答错的都错在哪 | 退步最集中的子集 |
|---|---|---|---|
| RefCOCO val（10,834 条） | −1.5（新答错 306，新答对 139） | 80% 是框错了（246 条），20% 是被判不存在（60 条） | 长表达（≥6 词）−4.4；带关系词的 −2.3 |
| gRefCOCO 无目标（8,905 条） | −2.2（469 / 270） | 全部是把无目标判成了有 | 短表达（≤2 词）−5.7；不含类别词的 −4.3 |
| robust-ref 中文（2,479 条） | −5.3（191 / 60） | 判不存在 72，框错 71，把无目标判成有 48 | 3–5 个字的 −6.1；带方位词的 −5.8 |
| robust-ref 关系型无目标（154 条） | −16.2（35 / 10） | 全部是把无目标判成了有 | 带关系词的 −15.8 |

## 逐项归因：最可能的数据来源

### 1. 关系型无目标 −16：缺一类负例

退步的例子：

- 电视左边那个东西（p 从 0.38 升到 1.00）
- 餐桌旁边的那个东西（0.42 → 0.98）
- the sports item left of the chair（0.00 → 0.52）

`catfree_scenes.py` 只造了一种关系负例：图中有这个类的物体，但没有一个满足这个关系。它没造"这个类在图里根本不存在 + 关系"的负例，而 robust-ref 的关系型负例大多正是这一种。另外，泛称词"东西 / thing"覆盖所有物体，"没有任何物体在锚点左边"这种条件几乎不成立，所以按我们的生成规则，"X 旁边的那个东西"在训练里永远是正例。

结果，2.4 万条关系正例实际教会了一条捷径：锚点在，加上一个关系词，就判存在。

**v1.3 怎么改**：

- 关系负例补上"类不存在 + 关系"一类。
- 用"东西 / thing"的关系负例，改成规则核对"锚点该侧确实没有任何标注物体"。
- 关系正例和负例按 1:1 配比。

### 2. gRefCOCO 无目标 −2.2：单实例方位正例的捷径

退步的例子：

- left seat（0.02 → 0.71）
- suitcase on the left side（0.00 → 0.78）
- the large giraffe on the right side（0.32 → 0.78）
- chest right（0.25 → 0.91）

这些都是短的"方位词 + 名词"，而且所指的东西在图里不存在。v1.2 加了 3.2 万条 `pos_pos_sole`（"the X on the left"，X 是图里唯一的那一个），配的负例只有 `neg_position`：X 存在，但在另一侧。缺的是"方位词 + 图里没有的 X"这一类负例。

此外，5.4 万条泛称正例（"that animal""那个家具"）大多也是短表达，进一步推高了模型对短句说"有"的倾向。

**v1.3 怎么改**：

- 给 `pos_pos_sole` 配上"方位词 + 不存在的类别"负例，可以由规则从 COCO 生成。
- 泛称正例和泛称负例的比例从 3.4:1 降到约 1.5:1。

### 3. RefCOCO −1.5：人写表达的回放太少

退步主要是框错，不是拒答。最差的是带锚点的关系句。

- guy left of umbrella：IoU 0.79 → 0.16
- person right of umbrella：0.86 → 0.18
- orange below big one left：0.88 → 0.12

v1.2 里 RefCOCO/+/g 人写表达的回放只有 7.9 万题，约为 v1.1 的 36%（v1.1 是 22 万）。与此同时，自然图像 box 题的四分之三来自模板或 LLM 写的句子（Glance-Data 27.8 万、无类别词 21.8 万）。其中的关系句是"泛称 + 关系 + 有名字的锚点"，和 RefCOCO"有名字的目标 + 关系 + 锚点"的结构正好相反。

一个可能的解释是：模型更容易把框落到锚点或相邻物体上。另有 60 条被判为不存在，例如 "a chair"（0.998 → 0.047）。原因是 Glance-Data 的 `single` 视图去掉了多实例的裸类别正例（它们是多目标题），所以多实例场景下的裸名词失去了正例支撑。

**v1.3 怎么改**：

- RefCOCO/+/g 回放恢复到 v1.1 的量（约 22 万题）。
- 多实例的 `cat_all` 以"只监督存在、不监督框"的方式放回单框训练。多框 head 上线后，这部分改由它来监督。

### 4. 中文 −5.3：中文难负例多于中文人写正例

退步的例子：

- 坐在绿色沙发上的一个男的（0.97 → 0.26）
- 一只全白、正看着狗的山羊（1.00 → 0.43）
- 穿蓝衬衫戴眼镜抬头看的男的（1.00 → 0.31）

这些都是带多个属性的长中文描述。v1.2 的中文监督里，Glance-Data 中文难负例（hneg_attribute 和 hneg_relation）约 4.5 万条，句子长、属性多；能与之对应的中文长正例只有 Glance-Data 的 long / medium，约 1.9 万条。无类别词数据的中文是短句。一致性锚点全是英文。

模型因此学到"中文长句、属性多，就倾向于判无"。这和 S3 sprint 的结论（只加中文和改写数据并不能提升）可以同时成立：问题不在于中文数据不够，而在于中文正负例的形状不匹配。

**v1.3 怎么改**：

- 加入中文版的 RefCOCO train 人写表达（vLLM 翻译，规则校验，不用 eval 图），作为中文长正例，并让它们和英文原句组成一致性组，英文原句作锚点。
- 中文难负例与中文长正例按 1:1 配比。

这一条和当初"不需要中文翻译"的判断相反。证据就是本表：中文退步主要来自长描述被拒，而 Glance-Data 的中文阶梯没能补上这一块。

## v1.3 配比建议（相对 v1.2）

| 部分 | v1.2 | v1.3 建议 |
|---|---|---|
| RefCOCO/+/g 人写表达回放 | 7.9 万 | 约 22 万（恢复到 v1.1） |
| 中文人写长正例（翻译 RefCOCO train） | 0 | 约 6 万，与英文原句成组 |
| Glance-Data 中文 hneg | 约 4.5 万 | 约 3 万，与中文长正例 1:1 |
| 关系：正例 / 负例 | 2.4 万 / 1.6 万（缺"类不存在"） | 2.4 万 / 2.4 万（加"类不存在 + 关系"） |
| 泛称：正例 / 负例 | 5.4 万 / 1.6 万 | 4 万 / 2.7 万 |
| `pos_pos_sole` | 3.2 万，只配 `neg_position` | 2.4 万，配 `neg_position` 和"方位词 + 不存在类别"各 1.2 万 |
| 多实例裸类别（cat_all） | 0（单框视图里被去掉） | 约 2 万，只监督存在 |
| 文本 / GUI 回放 | 30 万 / 19 万 | 不变（OpenDecisions 和 GUI 都守住了） |

这些都是从数据形状推出的归因，没有做消融。v1.3 开训前，最好先用一次约 800 步的短跑核对前两条（关系负例、方位词负例）：S3 的经验是 800 步就足以看出这类 shortcut 的方向。
