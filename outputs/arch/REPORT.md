# Glance 架构改进实验：第一阶段与第二阶段汇报

2026-11-20。分支历史已迁到 `Vision-Decision/glance-core`（`main`）。下表每一行都有 `outputs/arch/<exp>/summary.md` 和 json，HF 上的逐行结果路径写在各自的 summary 里。

## 一句话
零训练的两步组合把 ScreenSpot-Pro 原生分辨率从 50 提到 **68.75**，共享前缀保持不变：
1. GUI 输入把 LoRA 增量按 α = 0.5 缩放；
2. 每个问题把高分辨率裁剪图放进自己的问题块，并让块内 token 看不到整图 token。

实验 1 还纠正了一个归因：Glance 比底座低的 9 个点，主要来自 LoRA 遗忘，而不是 patch 网格。报告里排名靠前的几个候选结论，有两个被否定：解析框质量、免训练的 ĝ×s 多框。所有训练方案（LoRA 位置、自生成回放、训练 zoom 步）都没有超过对应的零训练基线。

## 对计划和假设的影响
- **假设变了。** SS-Pro 的差距主要是遗忘，不是网格。在这个混合模型上，遗忘对 LoRA 放在哪里不敏感；推理时按输入类型缩放 α 是目前最有效、成本也最低的手段。
- **结论调整。**
  - 撤下"质量从框输出解析得到"。
  - 新增两条有反事实对照的结论：（i）同一底座下，读出方式决定多条目召回会不会崩；（ii）块内注意力隔离的 zoom 在共享前缀下超过另起 prefill。
  - 速度叙事改为"粗前缀 + 每题 zoom"随问题数扩展。
- **v1.2 数据要注意。** 诊断集的模板化负例可以只看文本识别出来，需要配文本基线，或者改用外部 B 集。
- **需要方向性决定（请示）：**
  1. 是否把"GUI 路径 α"和块内 zoom 正式写进推理 API，以及发布的协议说明。我们的 zoom 数字属于 zoom 赛道，不是单次 prefill 协议。
  2. 第二阶段剩下的预算是投到任务门控训练（GUI 样本在训练时也用小 α，或单独的 GUI adapter），还是按原计划继续做计数最小对和路由头。
