# Exp 1：LoRA 增量按 α 缩放（免训练）——ScreenSpot-Pro 的下降大部分来自遗忘

**结论。** 把 v1.1 的 LoRA 增量乘以 α（W = W₀ + α·ΔW，各个头不动）之后，ScreenSpot-Pro 原生分辨率单调上升：

| α | 1.0 | 0.85 | 0.7 | 0.5 |
|---|---|---|---|---|
| SS-Pro | 49.8 | 52.6 | 55.3 | **58.1** |

底座生成式是 59.9。相对 α = 1 的配对差值分别为：
- α = 0.7：+5.6 [+4.0, +7.1]
- α = 0.5：+8.4 [+6.4, +10.2]

α = 0.7 时 RefCOCO 基本不变：testA 96.1（α = 1 时 96.0），testB 92.4（92.7），val 94.7（94.9），gRefCOCO 存在判断 AUROC 0.979（0.980）。gRefCOCO N-acc 在固定阈值 0.5 下从 0.860 降到 0.820，但这只是阈值漂移：把阈值调到和 α = 1 相同的召回率，N-acc 是 **0.863**，与 α = 1 的 0.860 相当。α = 0.5 开始伤到 COCO：testB −2.8，val −1.6。

所以 SS-Pro 底座与 Glance 之间 9 个点的差距，**大部分是 LoRA 增量覆盖掉了底座的 GUI 能力，即遗忘**，而不是 patch 网格读出的限制。这改变了报告里的归因：报告认为差距"一部分是网格，一部分是遗忘"，实测遗忘占大头。剩下的部分归像素：zoom 在此基础上再加 7–10 点（exp 2）。

**免训练就能用的结论：** 对 GUI 截图把 α 设为 0.7，再重新拟合存在门控的温度或阈值，SS-Pro 涨 5.6 点，其他指标的代价不超过 0.3 点。这同时是报告中"任务门控 LoRA"（第 15 项）最便宜的版本：按输入类型选 α，一张图只做一次 prefill，共享前缀不受影响。

## 设定与来源
- 模型：v1.1（`Vision-Decision/glance-train-ckpts-legacy:v1.1/ckpt_final.pt`），用 `arch.common.set_lora_scale` 缩放全部 LoRA 模块。
- SS-Pro：1,581 题，原生分辨率（≤16384 token，不放大），`evals/sprint/infer.py` 的同一套 harness。CI 是按题的配对 bootstrap。这里 α = 1 得 49.8，sprint 报告的官方数字是 50.66，差异来自 batch 打包下的 bf16 数值。
- COCO：RefCOCO testA/testB、gRefCOCO val merged（eval.py 协议）。
- α = 0 时头在底座隐状态上完全失效（Acc 0），说明头和 LoRA 是绑在一起训练的，不能直接摘掉 LoRA。
- 逐行结果：`Vision-Decision/glance-train-data:arch/alpha/`；代码：`arch/alpha/{run,analyze}.py`；数字：`results.json`。

## 对第二阶段的影响
"放在哪里、怎么防遗忘"（LoRA 位置、自生成回放、KL-to-base）是收回 SS-Pro 最有希望的训练方向。判定标准见 `outputs/arch/phase2/DECISION_forgetting.md`。新的参照线是 α = 0.7 的免训练结果：**训练方案至少要打平 α = 0.7 的 55.3 / 96.1 / 92.4 才算有价值。**

## 追加：v1.2 和 VenusBench-GD（2026-11-20）
- **v1.2**（`results.json` → `v1.2`）：SS-Pro 在 α = 1 / 0.7 / 0.5 下为 49.7 / 57.1 / **60.0**，α = 0.5 时已经超过底座的 59.9。配对差值：α = 0.7 时 +7.4，α = 0.5 时 +10.3。RefCOCO 在 α = 0.7 时 testA 95.1（α = 1 时 95.1）、testB 90.5（91.5）；gRef N-acc 在同召回率下为 0.846（0.838）。结论和 v1.1 一致，而且 v1.2 的增益更大。
- **VenusBench-GD，v1.1**（`venus_v1.1.json`；用的是我们自己的打分，没有重跑官方 UI-Venus 评测器）：

| α | 正例点击 | 拒答 N-acc（阈值 0.5） | 拒答 N-acc（保持 α = 1 的正例接受率） |
|---|---|---|---|
| 1.0 | 55.4 | 0.818 | 0.818 |
| 0.7 | 62.9 | 0.722 | **0.880** |
| 0.5 | 65.6 | 0.610 | **0.912** |

阈值固定在 0.5 时，α 越小越容易接受，拒答下降。但只要按 α = 1 的接受率重新取阈值，拒答反而**更好**：0.818 → 0.880 → 0.912。正例点击也提高了 7.5–10.2 点。所以 GUI 路径用小 α，再配一个按路径单独标定的存在阈值或温度，在 GUI 的定位和拒答两方面都更好。
