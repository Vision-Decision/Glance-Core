# Exp 6：GDN 状态是不是瓶颈？在图中找针、注意力屏蔽、分辨率扫描（均免训练）

**结论。** Glance 的读出方式不受"条目数"瓶颈影响：合成 GUI 画布上的按钮从 8 个加到 512 个，视觉 token 数固定为 1,600，Glance v1.1 的点击命中率始终在 **98–100%**。同一个 Qwen3.5-4B 底座改用生成式坐标输出，到 N = 128 时降到 51%，N = 512 时只剩 11%。纯注意力的 Qwen3-VL-4B 也会掉，但掉得慢一些（71% / 23%）。所以，用生成式读出时，混合模型的召回确实比纯注意力衰减得早；但 Glance 的头本身是在缓存的视觉 token 上做 patch 检索，绕开了这一问题。弱点 5 不应写成"GDN 是瓶颈"。准确的说法是：混合骨干加上生成式解码会出现召回断崖，而 Glance 的读出没有这个断崖。

屏蔽实验进一步说明了图像信息到达问题的通路：
- **只走 GDN 状态**（问题块在 8 个全注意力层里看不到图像 token）：needle 上命中率直接降到 0–18%，存在召回为 0。RefCOCO 的中心命中还有 68.6%，但 Acc@0.5 只有 29.7%。递归状态只携带粗略的"大概在哪里"，带不了"哪个按钮"。
- **只走注意力**（问题块的 GDN 状态清零）：RefCOCO 基本不受影响（Acc@0.5 92.4，对照 95.1）。needle 上则随 N 变差（N = 8 / 64 / 512 时为 95 / 54 / 14%）。GDN 状态在多条目场景里起辅助作用，最终的检索仍由注意力层完成。

## 结果（`summary_gen.json`、`ablate_v1.1.json`）

缺席问题：Glance 的 N-acc 在 0.96–1.00 之间。生成式模型输出 [-1,-1] 的拒答率在 N = 512 时降到 0.12（混合）和 0.60（纯注意力）。

**分辨率扫描**（ScreenSpot-Pro 固定的 400 题子集，两者都用 Qwen3-VL 官方的点坐标提示）：Qwen3.5-4B 在 1024 / 4096 / 16384 个视觉 token 下为 33.3 / 50.8 / 51.8，Qwen3-VL-4B 为 35.3 / 53.0 / 54.8。各档差距 2–3 点，CI 重叠。两者随分辨率的走势相同，看不到混合模型特有的分辨率瓶颈。

## 解读与注意事项
- Qwen3.5-4B 和 Qwen3-VL-4B 的训练数据不同，所以"混合 vs 纯注意力"的生成式对比不是受控实验，只是一致性证据。受控的部分是同一个模型上的屏蔽实验。
- needle 画布的 token 数固定，控件大小固定，变化的只有条目数（Zoology MQAR / JRT 的预测变量）。
- 可用的表述是：混合骨干加生成式读出，在多条目召回上会先于纯注意力模型崩溃；Glance 的 patch 检索读出在 512 个条目时仍保持 99%。这是读出方式的结构优势，并且有反事实对照（同一底座的生成式）。
