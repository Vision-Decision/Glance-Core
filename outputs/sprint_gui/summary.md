# GUI grounding 冲分 sprint 报告

在官方协议下，ScreenSpot-Pro 从 **29.3 提到 50.7**，仍比底座生成式（约 56）低约 5 个点。提升来自两处：推理改用原生分辨率（不需训练），以及换成 v1.1 checkpoint。两次 GUI 专精续训都没有带来增益。zoom-in 赛道最高 **62.2–62.4**，超过底座的无 zoom 数字，但低于 KV-Ground-4B（67.0）和 UI-Venus-1.5-8B（68.4）。ScreenSpot-v2 只到 **90.1**，没超过底座的 93.4。

## 有效手段排名（按 SS-Pro 增益）

1. **原生分辨率推理**，不用训练，属于标准协议：v1 从 28.9 到 39.3（+10.4）。
   - 之前 4K 截图被压到 2048 token。
   - 分辨率扫描：2048 为 28.9，4096 为 38.6，8192 为 39.2，原生为 39.3。
   - 最小目标从 4.3 到 12.4。
2. **v1.1 配方**：原生分辨率下从 39.3 到 50.7（+11.4）。
   - icon 从 25.2 到 40.7，Dev 类软件从 37.1 到 54.9。
3. **两阶段裁剪放大**（zoom 赛道）：+10 到 +18。
   - v1 从 39.3 到 58.1，v1.1 从 50.7 到 60.5。
   - 主要修小目标：最小目标从 27.0 到 45.6，icon 从 40.7 到 54.3。
   - 裁剪比例 0.25 好于 0.4；再级联一次只多 0.1，不值。
4. **多候选 zoom + presence 门控选择**：在单候选 zoom 上再 +1.0 到 +2.2。
   - 5 个 checkpoint 上方向一致：v1 +2.1，v1.1 中间版 +1.0，ft1 +2.2，v1.1 final +1.8，ft2 +2.5。
   - 任一候选命中的上限约 65.8。
   - 这条规则是在测试集上从 5 条规则里挑的，报告时要注明。
5. **解码器选择**：只对旧模型有用，不能算通用收益。
   - v1 上，用中心分布的 3×3 局部加权点代替框中心，+2.3。
   - 到 v1.1 这个优势消失，所以默认解码器（框中心）不变。

## 无效或负面结果

- **ft1（GUI 专精续训）**：从 v1.1 中间 checkpoint 起，纯 GUI 数据，35.8 万题，899 步。
  - SS-Pro 原生 49.7，起点约 49.5，增益在噪声内。
  - SS-v2 89.9，Venus 官方 overall 59.2。
  - 原因：v1.1 已经包含同源的 GroundCUA 和 OS-Atlas，同分布数据加多了不涨。
- **ft2（ft1 + zoom 尺度裁剪训练）**：裁剪外的元素当作已验证的"不存在"负例，322 步。
  - SS-Pro 原生 50.4，zoom 59.5，多候选 zoom 62.1，SS-v2 89.2，都没超过 v1.1 final。
- **多尺度相乘集成**：SS-Pro 从 39.3 降到 37.8。
- **跨 checkpoint 集成**：无收益。
- **SS-v2 上做 zoom**：从 90.1 降到 86.6，图本身不大，裁剪丢了上下文。
- **SS-Pro 首遍 ×2 放大**：单卡太慢，已中止，没有结论。
- **v1.1 训练后段**基本不再涨 SS-Pro：09:06 为 49.5，约 11:20 为 49.5，final 为 50.7。

## 失败分桶（v1.1 final，原生分辨率）

- **SS-Pro**：
  - 按类型：icon 40.7，text 56.8。
  - 按面积：最小一档（小于屏幕 0.01%）27.0，最大一档 74.6。
  - 按软件：Creative 41.1 最差，OS 45.4，CAD 46.0。
  - 剩下的主要瓶颈是 32px patch 粒度下的超小图标。
- **Venus**：
  - 推理类指令只有 18.1，功能描述类 44.1，web 平台 41.6。
  - 训练时 box 问题被截断到 40 token，长指令基本没见过。
- **SS-v2**：短板是 web 85.6 和 icon 86.1。

## 偏向我们的选择

- 原生分辨率：官方没有规定输入分辨率，属于合规选择。
- SS-v2 的 90.1 是在同一个 checkpoint 的两种分辨率里取高者，等于在测试集上选设置，差距在噪声内。
- zoom 和多候选 zoom 是单独赛道，需要额外 1–3 次 prefill，不能和无 zoom 的榜单混排。
- Venus 拒答阈值固定为 0.5，没有调。

## 下一步建议

1. 把 zoom + presence 选择做进推理 API，作为 agent 模式。零训练，SS-Pro +10 左右。
2. 训练时把问题长度上限从 40 token 提到 96 以上，并补推理类和功能描述类指令数据，针对 Venus 推理类和 web 短板。
3. 超小图标需要更细的定位粒度，比如不做 2×2 合并的 16px patch 中心头。
4. 同分布 GUI 数据已经饱和，不建议再投入。
